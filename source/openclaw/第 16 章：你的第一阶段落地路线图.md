# 第 16 章：你的第一阶段落地路线图

> **这一章解决什么问题？**
> 前 15 章教了你很多概念、命令、设计原则、安全规范。现在到了把这些知识转化成行动的时候。你可能会有一种"学了很多但不知道从哪儿开始"的感觉——这一章就是解决这个问题的。
> 三周的阶段性目标，每周聚焦 3-4 件事。做完这三周，你就有了一套真正运行中的 OpenClaw 系统——不是演示用的，是你每天真正在用的。

---

## 16.1 第一周：基础搭建

**核心目标：让系统跑起来，手动完成几个真实任务。**

### 16.1.1 跑通本地 Gateway

对应章节：第 4 章（安装、初始化与运行路径）

具体步骤：
1. 安装 OpenClaw
2. 运行 `openclaw configure` 完成初始设置
3. 配置至少一个模型（建议从你已有的 API Key 开始）
4. 运行 `openclaw gateway start` 确认 Gateway 正常启动
5. 运行 `openclaw health` 确认系统健康

**完成标志：** `openclaw health` 返回正常状态。

### 16.1.2 建立 2-3 个 Workspace

对应章节：第 7 章（Workspace 与目录策略）

不需要一次建完所有 Workspace。第一周先建这些：

```
workspaces/
├── news-watcher/          # 资讯巡检用
│   ├── staging/
│   └── validated/
├── kanji-staging/         # 汉字検定数据用
│   ├── staging/
│   └── validated/
└── prototype-lab/         # 原型验证用
```

**完成标志：** 目录结构创建完毕，每个 Workspace 下有 `staging/` 和 `validated/` 子目录。

### 16.1.3 手动执行 3 个真实任务

对应章节：第 5 章（命令行总览）、第 6 章（Agent 设计方法论）

不要急着做自动化——先手动运行 Agent，感受完整的流程：

**任务 1：** 让 Agent 去一个新闻源抓取今天的 AI 资讯，保存到 `news-watcher/staging/`

**任务 2：** 让 Agent 从一个汉字学习网站提取几个汉字的数据，保存到 `kanji-staging/staging/`

**任务 3：** 让 Agent 把任务 2 抓到的汉字数据整理成标准 JSON 格式

每个任务完成后手动检查输出——文件是否存在？内容是否合理？格式是否正确？

**完成标志：** 三个任务的输出文件存在且内容基本正确。

### 16.1.4 学会看 logs 和 doctor

对应章节：第 14 章（日志、排障与运行维护）

```bash
openclaw logs --tail 20
openclaw doctor
```

**不需要等到出问题才看日志。** 在一切正常的时候看一看——了解正常的日志长什么样，这样出问题时你才知道哪里不正常。

**完成标志：** 能看懂 `logs` 输出中的关键信息，`doctor` 没有报告严重问题。

### 第一周结束时你应该拥有的

- 一个正常运行的 Gateway
- 2-3 个结构清晰的 Workspace
- 3 次成功的手动任务执行记录
- 对日志和诊断工具的基本熟悉

## 16.2 第二周：自动化与隔离

**核心目标：把手动流程变成自动化，引入 Sandbox 隔离。**

### 16.2.1 给 1 个 Agent 上 Sandbox

对应章节：第 8 章（Sandbox 学习专题）

选择一个需要执行外部命令的 Agent（比如需要运行 `curl` 或 `python` 脚本的采集 Agent），给它配置 Sandbox。

步骤：
1. 确认 Docker 已安装并运行
2. 修改 Agent 配置，设置 Sandbox
3. 配置挂载路径（只挂载必要的目录）
4. 配置网络策略（只允许必要的域名）
5. 测试 Agent 在 Sandbox 中是否能正常工作

**完成标志：** Agent 在 Sandbox 内成功执行任务，产出符合预期。

### 16.2.2 建立 1 个 Daily Cron

对应章节：第 9 章（Cron 与自动化专题）

选择一个你想每天自动执行的任务（建议从资讯采集开始——"每天早上 8 点抓取 AI 新闻"）。

步骤：
1. 编写 Cron 配置（表达式 + Agent + 参数）
2. 设计幂等性——如果同一天执行两次，不应该产生重复数据
3. 注册 Cron 任务
4. 等一天验证是否自动触发
5. 或者手动触发一次测试

**完成标志：** Cron 任务至少自动执行一次，输出文件符合预期。

### 16.2.3 输出 1 份稳定日报

对应章节：第 10 章（信息采集与结构化抽取）

把 Cron 的输出格式化为你日常使用的格式——一份简洁的 AI 新闻日报 JSON 文件：

```json
{
  "date": "2025-01-16",
  "source": "collector-ai-news",
  "articles": [
    {
      "title": "...",
      "source": "...",
      "summary": "...",
      "url": "..."
    }
  ]
}
```

**完成标志：** 连续 3 天的日报文件存在且格式一致。

### 16.2.4 完成 1 个 JSON Staging 流程

对应章节：第 10 章 + 第 11 章（结构化抽取 + 整理）

完整走通"采集 → staging → 验证 → validated"的流程：

1. Agent 采集原始数据，写入 `staging/`
2. 你（或 curator Agent）检查数据质量
3. 合格的数据移动到 `validated/`
4. 不合格的数据留在 `staging/` 并标注原因

**完成标志：** `validated/` 目录下有经过验证的数据文件。

### 第二周结束时你应该拥有的

- 至少一个 Agent 在 Sandbox 中运行
- 至少一个每日自动执行的 Cron 任务
- 连续几天的结构化输出
- 一个完整的 staging → validated 数据流

## 16.3 第三周：场景落地

**核心目标：把系统的输出变成你真正使用的东西。**

### 16.3.1 形成汉字検定采集样例库

对应章节：第 10 章（信息采集与结构化抽取）

目标不是采集所有汉字——而是形成一个"示范级别"的样例库：

- 覆盖 3-5 个级别（准 1 級、1 級、2 級等）
- 每个级别至少 10-20 个汉字的完整数据
- 数据格式统一、字段完整（汉字、级别、音读、训读、词组、例句）

这个样例库有两个用途：
1. 验证你的数据采集和整理流程是否正确
2. 作为后续扩大采集规模的模板

**完成标志：** 一个包含 50-100 个汉字完整数据的 JSON 文件，格式正确、字段完整。

### 16.3.2 形成 3 个课程模块草稿

对应章节：第 11 章（结构化整理与课程模块化）

基于采集到的汉字数据，让 curator Agent 生成 3 个课程模块的草稿：

- 模块 A：入门级（按笔画数分组的基础汉字）
- 模块 B：按读音关联的汉字组
- 模块 C：按语义领域分组的汉字（比如"教育相关汉字"）

每个模块包含 3-5 个 Lesson，每个 Lesson 包含 5-10 个汉字卡片。

**完成标志：** 3 个模块的 Markdown 或 JSON 草稿文件，结构清晰、内容可读。

### 16.3.3 完成 1 个前端原型 Demo

对应章节：第 13 章（项目原型验证与开发协作）

用 Agent 生成一个简单的前端 demo——汉字检定搜索页面。基于样例库的数据：

- 一个搜索页面（输入汉字或读音，展示匹配结果）
- 使用 mock 数据（就是你的样例库 JSON）
- 不需要后端——纯前端 + 静态数据即可

**完成标志：** 在浏览器中打开 demo，输入汉字能看到搜索结果。

### 第三周结束时你应该拥有的

- 一个有实际内容的汉字样例库
- 3 个可以继续完善的课程模块草稿
- 一个可以体验的前端原型

## 16.4 第一阶段明确不做的事

同样重要的是知道第一阶段**不应该**追求什么。以下四点是常见的过度优化陷阱：

### 16.4.1 不追求全自动

你的目标是"半自动"——Agent 做大部分工作，你做最后的审查和确认。

追求全自动意味着你要处理所有边界情况、异常恢复、数据回滚——这些在第一阶段是不划算的。先建立信任，等你连续运行三个月都没问题，再考虑减少人工参与。

### 16.4.2 不追求全量采集

你只需要采集足够验证流程的数据量——50-100 个汉字、一周的新闻摘要。

全量采集意味着更多的存储、更复杂的去重逻辑、更多的 API 调用费用。这些问题第一阶段不需要面对。

### 16.4.3 不追求生产级发布

你的原型 demo 不需要部署到公网、不需要域名和 SSL、不需要 CDN 和监控。

在本地跑起来、自己能用就够了。生产级发布是第二阶段的事。

### 16.4.4 不追求一个 Agent 包打天下

不要试图设计一个"超级 Agent"来完成所有任务。

每个 Agent 专注一件事——collector 只采集、curator 只整理、importer 只导入。这是第 6 章的核心设计原则，在第一阶段尤其重要。

## 16.6 如果这里失败，先检查什么

**"第一周卡在 Gateway 启动"**
→ 回到第 4 章，确认安装步骤没有遗漏。运行 `openclaw doctor` 看诊断结果。

**"第二周 Cron 任务不触发"**
→ 确认 Gateway 在运行、确认 Cron 表达式正确、确认时区设置。回到第 9 章复习。

**"第三周不知道该采集什么数据"**
→ 从最简单的开始——找一个提供汉字数据的公开网站，先采集 10 个汉字。回到第 10 章复习采集流程。

**"做到一半觉得太复杂了"**
→ 缩小范围。第一阶段的最低目标是：Gateway 能跑 + 一个 Agent 能工作 + 一个 Cron 能触发。其他都是加分项。
