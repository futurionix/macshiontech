## 我学 OpenClaw 是为了：

建立一套半自动的内容采集与数据加工流水线——每天自动巡检技术资讯、定期抓取日语汉字检定资料、将散落的学习素材整理成结构化课程模块，最终通过受控流程写入数据库。同时用 Agent 快速验证产品原型想法。

## 我的自我定位

### 四个核心问题的回答

1. **聊天工具还是执行系统？**
   → 执行系统。我需要它替我自动跑任务，不是用来对话的。

2. **本地研发助手还是内容采集流水线？**
   → 以内容采集流水线为主，原型验证为辅。先把采集 → 整理 → 入库跑通，再扩展到开发协作。

3. **建议型 Copilot 还是执行型 Operator？**
   → Operator 模式。我希望定义好规则后让它自己跑，不需要我一直盯着，只在关键节点做人工审查。

4. **是否接受周期性自动运行？**
   → 是。这意味着安全章节（第 3 章）和自动化章节（第 9 章）是必修课，不能跳过。

## 我的具体使用场景

### 场景 1：日常资讯巡检

- **描述：** 每天早上自动抓取 AI 技术资讯和日本教育类新闻，生成结构化摘要
- **输入来源：** 3-5 个技术博客 / 新闻站 RSS 或网页
- **输出格式：** JSON（标题、来源、摘要、URL、日期）
- **频率：** 每天早上 8:00
- **是否需要自动运行：** 是（Cron）
- **对应章节：** 第 9 章（Cron）、第 10 章（信息采集）
- **涉及 Agent：** collector-ai-news、collector-jp-news

### 场景 2：汉字検定资料抓取与结构化

- **描述：** 从汉字学习网站采集汉字数据（读音、级别、词组、例句），整理为统一 Schema
- **输入来源：** 公开汉字学习网站、汉字検定参考资料页面
- **输出格式：** JSON（kanji / level / on_reading / kun_reading / compounds / examples）
- **频率：** 每周 1-2 次手动触发，后期改为自动
- **是否需要自动运行：** 第一阶段手动，第二阶段自动
- **对应章节：** 第 10 章（采集）、第 12 章（受控入库）
- **涉及 Agent：** collector-kanji、curator-kanji

### 场景 3：课程模块化整理

- **描述：** 将零散的日语 / IT 日語 / 汉字検定 / 英語学习素材整理为"模块 → 课时 → 练习"结构
- **输入来源：** 已采集并验证的汉字数据、手头的学习笔记
- **输出格式：** Markdown 或 JSON（模块标题 / 学习目标 / Lesson 列表 / 卡片内容）
- **频率：** 每周整理一次
- **是否需要自动运行：** 否（需要人工判断模块设计）
- **对应章节：** 第 11 章（课程模块化）
- **涉及 Agent：** curator-course

### 场景 4：产品原型快速验证

- **描述：** 用 Agent 生成汉字検定搜索页面、详情页、学习模块页的前端原型
- **输入来源：** 场景 2/3 产出的数据（mock 或真实）
- **输出格式：** React / HTML 前端代码 + mock JSON
- **频率：** 按需（有新想法时）
- **是否需要自动运行：** 否（手动触发，Sandbox 内运行）
- **对应章节：** 第 13 章（原型验证）
- **涉及 Agent：** prototyper

### 场景 5：数据库受控入库

- **描述：** 将验证通过的汉字数据和课程模块数据，通过 importer 写入 SQLite 测试数据库
- **输入来源：** `validated/` 目录下经审核的 JSON 文件
- **输出格式：** SQLite 数据库记录
- **频率：** 每次有新数据验证通过后执行
- **是否需要自动运行：** 否（必须人工 Approval 后执行）
- **对应章节：** 第 12 章（受控入库）
- **涉及 Agent：** importer-kanji

## 我的 Agent 设计清单

| Agent 名称 | 角色 | 主要职责 | Sandbox | 权限要点 |
|---|---|---|---|---|
| collector-ai-news | Collector | 每日抓取 AI 技术资讯 | 可选 | 只读网络 + 写 staging |
| collector-jp-news | Collector | 每日抓取日语教育新闻 | 可选 | 只读网络 + 写 staging |
| collector-kanji | Collector | 抓取汉字検定资料 | 推荐 | 只读网络 + 写 staging |
| curator-kanji | Curator | 校验汉字数据质量、标准化格式 | 否 | 读 staging + 写 validated |
| curator-course | Curator | 整理学习素材为课程模块 | 否 | 读 validated + 写 course-builder |
| prototyper | Prototyper | 生成前端原型代码 | 必须 | 读 validated + 写 prototype-lab |
| importer-kanji | Executor | 将验证数据写入测试数据库 | 否 | 读 validated + 写数据库（需 Approval） |

## 我的 Workspace 规划

```
workspaces/
├── news-watcher/              # 资讯巡检
│   ├── staging/               # 每日抓取的原始数据
│   ├── validated/             # 审核通过的摘要
│   └── logs/                  # 采集日志
├── kanji-staging/             # 汉字検定
│   ├── staging/               # 抓取的原始汉字数据
│   ├── validated/             # 校验通过的标准化数据
│   ├── failed-samples/        # 质量不合格的样本
│   └── logs/                  # 采集/校验日志
├── course-builder/            # 课程模块化
│   ├── sources/               # 待整理的素材
│   ├── modules/               # 产出的模块草稿
│   └── logs/
├── prototype-lab/             # 原型验证（隔离环境）
│   ├── kanji-search/          # 搜索页原型
│   ├── kanji-detail/          # 详情页原型
│   └── course-viewer/         # 课程浏览原型
└── importer/                  # 受控入库
    ├── pending/               # 待导入的文件
    ├── imported/              # 已导入的存档
    └── logs/
```

## 安全红线

1. 不让 Agent 直接写生产数据库——必须经过 staging → validated → Approval → 测试库 → 正式库
2. 不让 Agent 在 Sandbox 外执行 Shell 命令
3. 不让 Agent 访问不在白名单内的网络域名
4. 不让 Agent 删除 validated 目录下的文件
5. 不给 Agent 超出其职责的权限——即使"临时方便"
6. 不安装来源不明的第三方 Skill / Plugin
