# `openclaw help` 使用示例

```bash
openclaw models --help
# Show detailed help for the models command.
# 作用：查看 models 这组命令的详细帮助。
# 你可以把它理解为“专门查看模型相关功能说明”。
# 适用场景：你想了解 OpenClaw 怎么查看模型状态、配置模型、探测模型可用性时，用这个命令先看说明。
# 重点：它不会执行模型调用，只是打开帮助信息。

openclaw channels login --verbose
# Link personal WhatsApp Web and show QR + connection logs.
# 作用：登录某个聊天渠道，并显示更详细的日志。
# 示例注释里写的是 WhatsApp Web，所以这里通常表示：把你的个人 WhatsApp Web 会话接入 OpenClaw，并在过程中显示更详细的连接日志。
# 适用场景：你想把 OpenClaw 接到聊天平台上，让它能通过聊天收发消息。
# 重点：--verbose 表示输出更详细的过程信息，方便排查登录失败或连接异常。

openclaw message send --target +15555550123 --message "Hi" --json
# Send via your web session and print JSON result.
# 作用：向指定目标发送一条消息，并将结果以 JSON 格式输出。
# 你可以把它理解为“测试消息发送是否成功，并把发送结果结构化打印出来”。
# 适用场景：你已经接好了某个聊天渠道，想验证 OpenClaw 是否真的能把消息发出去，同时希望看到更适合调试的结果格式。
# 重点：--json 表示输出结构化结果，便于程序读取、日志记录或后续排查。

openclaw gateway --port 18789
# Run the WebSocket Gateway locally.
# 作用：在本地启动 Gateway，并指定端口为 18789。
# 你可以把它理解为“手动把 OpenClaw 的运行中枢启动起来，但不用默认端口，而是换一个端口运行”。
# 适用场景：默认端口被占用，或者你想明确控制 Gateway 运行在哪个端口。
# 重点：Gateway 是 OpenClaw 的核心运行服务，很多 agent、消息和自动化能力都依赖它。

openclaw --dev gateway
# Run a dev Gateway (isolated state/config) on ws://127.0.0.1:19001.
# 作用：在 dev 开发环境下启动一个隔离的 Gateway。
# 你可以把它理解为“启动一个实验用的 OpenClaw 环境，不污染默认环境”。
# 适用场景：学习、测试配置、试错、排查问题时优先使用。
# 重点：--dev 会将家目录隔离到 ~/.openclaw-dev/，使用独立的配置、凭据、会话历史和日志，并运行在单独的端口上。
#       类似地，--profile <name> 会隔离到 ~/.openclaw-<name>/。两者都是学习阶段非常推荐的用法。

openclaw gateway --force
# Kill anything bound to the default gateway port, then start it.
# 作用：强制启动 Gateway；如果默认端口已经被占用，会先清理占用该端口的进程，再启动 Gateway。
# 你可以把它理解为“端口冲突时的强制接管启动方式”。
# 适用场景：你之前启动过 Gateway 但没有正常关闭，或者默认端口被其他进程占用了。
# 重点：这是带有强制性的启动方式，适合排查端口冲突，但要注意不要误伤你本来需要的进程。

openclaw gateway ...
# Gateway control via WebSocket.
# 作用：这里不是一条完整命令，而是在提示你 gateway 这组命令还有更多扩展用法。
# 你可以把它理解为“gateway 不只是一个启动命令，它还有更多通过 WebSocket 控制和管理 Gateway 的能力”。
# 适用场景：你已经知道如何启动 Gateway，接下来想进一步探索它的控制、查询或管理方式。
# 重点：看到这种省略号写法时，通常表示“请继续查看该命令组的详细帮助”。

openclaw agent --to +15555550123 --message "Run summary" --deliver
# Talk directly to the agent using the Gateway; optionally send the WhatsApp reply.
# 作用：通过 Gateway 直接向 agent 发送一条任务请求，并可选择把结果真正发送给指定目标。
# 你可以把它理解为“让 agent 执行一个任务，然后把执行结果发到聊天对象那里”。
# 适用场景：你已经接好了聊天渠道，想测试 agent 不只是生成内容，而是能把结果真正投递出去。
# 重点：--deliver 表示真的发送，不只是本地执行；如果没有这个参数，通常更偏测试或中间过程。

openclaw message send --channel telegram --target @mychat --message "Hi"
# Send via your Telegram bot.
# 作用：通过 Telegram 渠道向指定目标发送一条消息。
# 你可以把它理解为“指定使用 Telegram 这个渠道，把消息发送给某个聊天对象”。
# 适用场景：你已经配置好了 Telegram bot，想测试消息发送是否正常。
# 重点：--channel telegram 明确指定了消息发送渠道，说明 OpenClaw 可以管理多个不同的聊天渠道，而不一定只依赖默认渠道。
```
