# 第 11 章：结构化整理与课程模块化

> **这一章解决什么问题？**
> 你的采集员已经在 staging 目录中积累了原始数据（第 10 章）。但原始数据本身没有价值——它需要被**整理、分类、编排**，才能变成可用的知识产品。
> 这一章的主题是"知识产品化"。以外语学习资料为主要场景，教你如何把零散的采集数据变成结构化的课程模块。方法论同样适用于其他领域——任何需要"把原始素材变成有组织的输出"的场景都可以参考。
> 这一章也会明确 Agent 在课程整理中的角色边界——它是课程编辑助手，不是最终教师。

---

## 11.1 整理不等于搬运

### 11.1.1 为什么"模块化"本质上是知识设计

把 100 条汉字记录从 staging 移到另一个目录——这是搬运，不是整理。

真正的整理意味着：

- **归类**：这 100 条汉字按什么维度分组？按级别？按主题（自然、人体、社会）？按学习阶段？
- **排序**：同一个分组里，哪个汉字先学？为什么？是按频率？按难度？按考试权重？
- **关联**：哪些汉字之间有关联？同一个部首的？读音相近容易混淆的？常一起出现的？
- **补充**：原始数据中缺了什么？需要补充例句？需要添加助记方法？需要设计练习题？

这些决策加在一起就是"知识设计"——你在决定学习者以什么样的路径来吸收这些知识。

### 11.1.2 为什么课程化要有学习目标、顺序和难度层次

一个好的课程模块不仅仅是"一堆内容的集合"，它需要：

**学习目标**：学完这个模块，学习者应该能做到什么？"能认读 50 个 3 级汉字"比"了解一些汉字"具体得多。

**顺序逻辑**：为什么先学 A 再学 B？是因为 A 是 B 的基础？还是 A 的难度低适合热身？顺序需要有理由。

**难度层次**：一个模块内的内容应该有难度梯度。从简单到复杂，让学习者感受到"可控的挑战"而不是"无差别的信息轰炸"。

## 11.2 从原始资料到课程模块

### 11.2.1 完整流程

```
原始素材 → 素材归类 → 主题抽取 → 难度分层 → 模块命名 → Lesson 拆分 → 练习设计
```

### 11.2.2 素材归类

把 staging 中的原始数据按照某个维度归入不同的桶。

**汉字检定场景的归类维度：**

| 归类维度 | 示例 |
|:---|:---|
| 级别 | 1 级、准 1 级、2 级、... |
| 部首 | 水部、木部、金部、... |
| 语义主题 | 自然、身体、情感、社会、政治、... |
| 学习阶段 | 入门、基础、进阶、冲刺 |

第一次归类建议用**级别**作为主维度——这是最自然、最符合考试逻辑的分组方式。

### 11.2.3 主题抽取

在每个级别内，可以进一步按主题组织。比如 3 级的汉字可以分为：

- 日常生活类（食、住、衣）
- 自然环境类（天气、地理、动植物）
- 社会活动类（工作、学校、交通）
- 抽象概念类（时间、程度、关系）

Agent 可以帮你做初步的主题分类——给它一批汉字和它们的含义，让它按语义相似度分组。但最终的主题划分应该由你（作为课程设计者）来确认。

### 11.2.4 难度分层

同一个主题内的汉字也有难度差异。影响难度的因素包括：

- 笔画数：笔画少的通常更简单
- 使用频率：日常高频使用的比罕见字简单
- 读音数量：只有一个读音的比多个读音的简单
- 字形复杂度：结构简单的比结构复杂的简单

Agent 可以基于这些因素对汉字做初步的难度排序。

### 11.2.5 模块命名

每个模块需要一个清晰的名称，让学习者一看就知道这个模块讲什么。

```
✗ 不好的命名：Module 3-A, Group B, Set 12
✓ 好的命名：3 级 · 日常生活篇 · 入门, 3 级 · 自然环境篇 · 进阶
```

命名规则建议：`{级别} · {主题} · {难度阶段}`

### 11.2.6 Lesson 拆分

一个模块可能包含几十上百个汉字。需要拆分成多个 Lesson，每个 Lesson 的学习量控制在合理范围内。

**参考标准：**
- 每个 Lesson 包含 5-10 个新汉字
- 每个 Lesson 的学习时间控制在 20-30 分钟
- 每个 Lesson 有明确的小目标（"学完这课你能认读这 8 个汉字"）

### 11.2.7 练习设计

每个 Lesson 应该配套练习。Agent 可以帮你生成练习题的草稿。常见的练习类型：

| 练习类型 | 说明 | Agent 能做什么 |
|:---|:---|:---|
| 读音选择 | 给汉字选正确读音 | 生成选项（含干扰项） |
| 汉字书写 | 给读音写汉字 | 提供书写提示（部首、笔顺） |
| 词组填空 | 在句子中填写正确汉字 | 生成带空格的例句 |
| 字义匹配 | 匹配汉字和含义 | 生成配对题 |

**注意：** Agent 生成的练习题必须经过你的审核。模型可能生成不准确的干扰选项或不自然的例句。

## 11.3 对外语学习资料的模块化原则

### 11.3.1 输入先行

语言学习的核心顺序是：先输入（听、读），后输出（说、写）。课程模块的设计应该遵循这个原则：

- 每个 Lesson 先展示新词/新字在上下文中的使用（输入）
- 然后要求学习者识别和理解（被动输入能力）
- 最后要求学习者主动使用（输出）

### 11.3.2 输出跟进

不要只有输入没有输出。每学完一批新内容，就应该有对应的输出练习：

- 学了 10 个汉字 → 用这些汉字造句
- 学了 5 个词组 → 用这些词组写一段话
- 学了一个语法模式 → 用这个模式做翻译练习

### 11.3.3 例句最小闭环

每个新学的词/字至少配一个例句。例句应该尽量只包含已学过的内容（或少量可推测的新内容），形成"最小闭环"——学习者能在不查字典的情况下理解大部分例句。

Agent 在生成例句时可能使用超出学习者水平的词汇。你的审核重点之一就是检查"例句中是否有太多学习者还没学过的内容"。

### 11.3.4 复习节奏

课程模块应该内建复习机制：

- 每 3 个 Lesson 后设一个复习 Lesson
- 复习 Lesson 涵盖前面所有 Lesson 的内容
- 使用不同于首次学习时的练习形式（首次是认读 → 复习时是书写，或反过来）

### 11.3.5 测试与反馈

每个模块结束后应该有一个模块测试，帮助学习者评估自己的掌握程度。

Agent 可以生成测试题和参考答案，但评分标准和反馈建议应该由你来设计（或至少审核）。

## 11.4 你的应用场景

### 11.4.1 日语学习资料模块化

把采集到的日语学习资料（汉字、语法、词汇）按照上述原则整理成课程模块。

**示例模块结构：**

```
modules/
├── kanji-grade3/
│   ├── 00-module-overview.md       # 模块概述和学习目标
│   ├── 01-daily-life-basic.md      # Lesson 1: 日常生活 · 入门
│   ├── 02-daily-life-advanced.md   # Lesson 2: 日常生活 · 进阶
│   ├── 03-nature-basic.md          # Lesson 3: 自然环境 · 入门
│   ├── 04-review-1.md              # 复习 1
│   ├── ...
│   └── module-test.md              # 模块测试
```

### 11.4.2 IT 日语对话卡

针对 IT 工作场景的日语对话，制作闪卡式学习资料。

**示例卡片：**

```json
{
  "id": "it-jp-001",
  "scenario": "プロジェクト進捗報告",
  "japanese": "今週の進捗を報告させていただきます。",
  "chinese": "让我来汇报一下本周的进展。",
  "context": "在周会上向团队成员报告项目进展时使用",
  "key_vocabulary": ["進捗", "報告", "させていただく"],
  "formality": "formal"
}
```

### 11.4.3 汉字检定辅助内容

基于采集到的汉字数据，生成辅助学习内容：

- 部首归纳表
- 易混淆字对比表
- 高频词组速查表
- 模拟测试卷

### 11.4.4 英语工作环境表达训练资料

如果你也有英语学习需求，同样的模块化方法论适用：

```
modules/
├── eng-work/
│   ├── email-writing/           # 邮件写作
│   ├── meeting-expressions/     # 会议表达
│   ├── code-review-comments/    # 代码审查评论
│   └── presentation-phrases/    # 演示报告用语
```

## 11.5 Agent 在课程整理里的角色

### 11.5.1 不是最终教师

Agent 不能替代你做课程设计的核心决策：

- **学习目标谁来定？** 你。Agent 不知道学习者的水平、需求和目标。
- **难度梯度谁来把关？** 你。Agent 对"什么对学习者来说难"的判断不够准确。
- **例句质量谁来审核？** 你。Agent 生成的例句可能不自然、不符合考试风格。
- **课程结构谁来决定？** 你。模块顺序、Lesson 容量、复习节奏都是教学设计决策。

### 11.5.2 而是课程编辑助手

Agent 能高效完成的事情：

| 任务 | Agent 的能力 | 你需要做的 |
|:---|:---|:---|
| 按主题分类汉字 | 根据含义做初步归类 | 审核分类是否合理 |
| 按难度排序 | 根据笔画、频率等指标排序 | 确认排序符合教学逻辑 |
| 生成例句 | 根据汉字和级别生成例句 | 审核例句的自然度和准确性 |
| 生成练习题 | 根据模板生成选择题、填空题 | 审核题目和答案的准确性 |
| 格式化输出 | 把内容整理为 Markdown 模块文件 | 确认格式符合你的规范 |
| 生成概述 | 为每个模块生成学习目标和概述 | 审核并调整 |

**核心原则：** Agent 做初稿和粗活，你做决策和质检。这个分工让你既能利用 Agent 的效率，又不放弃对课程质量的控制。

## 11.6 如果这里失败，先检查什么

**"Agent 的分类结果和我预期差距很大"**
→ 在 Prompt 中提供分类的具体规则和示例。不要只说"按主题分类"，而是说"按以下主题分类：日常生活（食、住、行）、自然环境（天气、地理）、社会活动（工作、学校）、抽象概念（时间、程度）"。提供 3-5 个分好的示例。

**"生成的例句不自然"**
→ 尝试在 Prompt 中指定例句的风格（"生成适合 JLPT N3 水平学习者的例句"）和约束（"例句长度不超过 20 个字"）。如果持续不满意，考虑使用更强的模型来处理例句生成。

**"模块结构太碎或太大"**
→ 调整 Lesson 的汉字数量参数。从 8 个开始试，太少就增加到 12，太多就减少到 5。找到一个你觉得"一次学习量刚好"的数字。

**"不确定从哪里开始"**
→ 从最小可行的模块开始。挑一个级别（比如 3 级）、一个主题（比如日常生活）、做一个只有 3 个 Lesson 的小模块。跑通整个流程后再扩展。
